## 1. 两版方案的取舍（因果链）

**第一版（未提交，已废弃）**：把"原子原语 + 锁"混在一个 `spin_.rs` 里——`Spin` 锁住数据，
`LockFlag` 锁住字；业务侧（`WeakChunkState`）直接调用 `try_once_compare_exchange_weak` /
`try_spin_compare_exchange_weak`，并自己算锁位掩码。

评审否决理由（保留，作为"为什么不这么做"的依据）：

1. **命名太泛**：`Spin` 表达不出"锁的是数据"；后续若加 `SpinRwlock` 之类就没有区分度，
   数据锁应叫 `SpinMutex`。
2. **锁信号位没做成配置项**：标准答案把"哪一位是锁信号"抽成 `TrMutexSignal<V>` 策略类型，
   由锁的 `S` 参数选择；第一版把最高位硬编码进弱槽位实现。
3. **锁住的内容没通过泛型体现**：标准答案是 `SpinningMutex<T, D, C, S, O>`，用 `UnsafeCell<T>`
   承载受保护数据；第一版只有注册表一个使用场景，业务侧仍在裸原子字上操作。
4. **`compare_exchange` 泄漏进业务逻辑**：`WeakChunkState` 里出现 CAS、掩码与"判据不成立"
   分支，这些属于锁的内部实现，业务只该看到"读 / 条件读改写 / 抢锁 / 释放"。
5. **模块重复**：`atomic_` 与 `spin_` 实际是一件事，合并为 `atomic_`。

### 2.1 锁信号位是配置项：`TrMutexSignal<V>`

```rust
pub(crate) trait TrMutexSignal<V: Copy> {
    fn is_acquired(val: V) -> bool;
    fn is_released(val: V) -> bool { !Self::is_acquired(val) }
    fn make_acquired(val: V) -> V;
    fn make_released(val: V) -> V;
}
```

- `MsbAsMutexSignal<V>`：最高位（默认）；
- `LsbAsMutexSignal<V>`：最低位（当前仅测试使用，用来证明"位可换"）；
- `V: TrBitWord` 是边界：需要 `& | ! <<`，因此 `bool` 这类不能做位信号锁。

需要别的位型时，实现 `TrMutexSignal` 并把它放到锁的 `S` 位置即可，锁本身不改。

### 2.2 锁住的内容是泛型：`SpinMutex<T, D, C, S, O>`

| 参数 | 含义 |
| --- | --- |
| `T` | **被锁住的内容**，由 `UnsafeCell<T>` 承载；`T: ?Sized`，因此该字段必须是最后一个 |
| `D` / `C` | 原子字值类型与原子单元类型（`usize` / `AtomicUsize`、`u32` / `AtomicU32`） |
| `S` | 锁信号策略（默认 `MsbAsMutexSignal<D>`） |
| `O` | CAS 内存序（默认 `StrictOrderings`） |

- `with_locked(|&mut T| ...)` 忙等加锁后执行闭包；`try_with_locked(max_try, ...)` 有界重试；
- `SpinMutexGuard` `Deref` / `DerefMut` 到 `T`，`Drop` 是**唯一解锁点**；
- `unsafe impl Sync/Send` 的判据是 `T: Send`——"锁住了什么"决定跨线程能力；
- `PreDropRegistry` 直接写成 `SpinMutex<Vec<PreDropEntry>>`，手写的 `UnsafeCell` 与
  `unsafe impl Sync/Send` 全部删除。

### 2.3 同字锁：`SpinFlag<D, C, S, O>`

状态与锁位必须共用同一个字时（`WeakChunkState` 的状态字）用它：

- `#[repr(transparent)]`，尺寸与原子字一致，不改变 `WeakChunkState` 的 8 字节布局；
- `read()` / `is_locked()`：无锁快路径，`read` 返回的位**不含锁位**；
- `try_update(op)`：无锁条件读—改—写，`op` 收到剔除锁位后的字、返回 `(新字, 结果)`，
  返回 `None` 即放弃；写回时保持锁位原状，因此不会与持锁者互相破坏；
- `try_acquire(max_try)` / `release()`：存在的手动抢锁入口，只服务于 `WeakChunkStateGuard`；
- `fetch_add` / `fetch_sub`：低位计数（弱引用计数）。

## 3. CAS 只出现在锁的逻辑里

**业务代码里不再出现 `compare_exchange`**；CAS 的调用点只有 `atomic_/spin_.rs` 的
`try_acquire` / `release` / `try_update` 三个函数。`cell_.rs` 只把 `compare_exchange_weak`
作为 `TrAtomicCell` 的抽象方法声明并转发给 `core::sync::atomic`。业务侧的形态：

| 位置 | 变化（相对收口前） |
| --- | --- |
| `WeakChunkState` | `weak_state_: AtomicU32` + 本地 `try_once_` / `update_` 与状态 CAS → `SpinFlag<u32, AtomicU32, MsbAsMutexSignal<u32>>`；业务方法只用 `read` / `try_update` / `fetch_add` / `fetch_sub` / `try_acquire` / `release` / `is_locked` |
| `WeakChunkState::compare_exchange_state` | 更名 `try_transition_state`（业务语义为"仅当当前是 `from` 时迁到 `to`"，不再带 CAS 词汇） |
| `PreDropRegistry` | `AtomicBool` + `UnsafeCell<Vec<_>>` + 手写 guard → `SpinMutex<Vec<PreDropEntry>>`（手写 `unsafe impl Sync/Send` 随之删除） |

`SpinFlag::try_update` 的闭包可能因并发踩踏被调用多次，因此必须只做纯计算；状态迁移的
"认领唯一"仍由闭包里的 `DataState` 判据保证，不需要额外锁。
