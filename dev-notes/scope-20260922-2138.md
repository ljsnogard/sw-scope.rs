# 先做单线程：RootScope 去用户化、去掉 RootShared、预留线程模式 marker

- 日期：2026-09-22 21:38
- 模块：`scope_` / `scope_inner_` / `smart_pointer_`
- 状态：**已落地当前阶段**。
- 相关：`scope-20260922-1423.md`（其 §8 跨线程锁计划已被本文取代）、
  `weak-20260922-1135.md`（PreDrop 与弱池）、
  `teardown-20260922-1911.md`（SharedScope 之后的清盘任务池设计）。

## 1. 当前决策

现阶段只实现**单线程 sw-scope**：

- `Root` / `Scope` / `Retain` / `Owning` / `Sharing` 都是 `!Send + !Sync`；
- 不实现 root 弱池、root 子链、pending 队列的跨线程同步；
- 类型系统上预留线程模式 marker，后续再扩展 `SharedScope`。

理由：

- 先把树、清盘、PreDrop、弱槽位生命周期在单线程下做正确；
- 避免同时处理“类型擦除 arena 的 Send 条件”和“全树结构锁”两个大问题；
- 参考 gc-arena：它直接用 `!Send + !Sync` 把整个 GC 宇宙限制在单线程内，
  因而不需要给 `T` 加 `Send` / `Sync` 约束。sw-scope 当前先采用同一策略。

## 2. RootScope 去用户化

**RootScope 不会再被包装成公开 `Scope` 返回，但 RootScope 的初始化是必须的。**

- `Scope::root(...)` 改成 `Scope::try_config_root(...)`：只初始化 / 配置 RootScope，
  返回 bool，不返回任何 `Scope`；
- 删除了 `Scope::new` 里的临时 root `Scope` 句柄；
- `Scope::new()` 现在直接以内部 root 域为父，创建并返回它的**子 Scope**；
- `Scope::drop` 不再需要“root 没有父域，防御性跳过”的分支。

所以：

```text
RootScope：内部管理员 / 分配器 / 弱池 / 注册表 / 根域节点
Scope：只代表 root 的子域，不回指 root 自身
```

root 仍然可以保留一个 `ScopeInner` 作为域树根节点，但它不是用户可持有的 Arena。

## 3. 移除 RootShared 概念

曾经的 `RootShared` 试图把 root 子链、pending 队列和弱池一起放进 root 锁，
这会把父子链从“父域局部状态”错误提升为“root 全局状态”。

现已彻底移除：

- `RootShared` 类型；
- `root_first_child_ / root_last_child_`；
- root 专用的 `root_scope_link_child_ / root_scope_unlink_child_`；
- root 侧待回收队列共享字段。

`RootExtension` 回到只持有真正 root 级资源：

```rust
pub(crate) struct RootExtension<const CELL_SIZE: usize> {
    weak_pools_: Option<NonNull<WeakPool<CELL_SIZE, RootExtension<CELL_SIZE>>>>,
    pre_drop_registry_: PreDropRegistry,
}
```

父子链 / sibling / pending 仍然放在 `ScopeInner` 上，按单线程逻辑维护。

后续若实现 `SharedScope`，正确方向是：

- 每个父域有自己的子链锁；
- `first_child_ / last_child_ / prev_sibling_ / next_sibling_ / parent_scope_`
  由该父域的子链锁保护；
- 锁序为 parent -> child；
- 只有 `WeakChunk` / `WeakPool` / `PreDropRegistry` / `TeardownTaskPool`
  这类 root 级资源共享 root 锁。

## 4. 新加入的类型与 marker

### 4.1 线程模式 marker

```rust
pub struct Local;
pub struct Shared;
```

- `Local`：当前唯一实现的模式，单线程使用；
- `Shared`：预留的跨线程模式，当前没有构造入口，也没有跨线程实现。

### 4.2 Scope 泛型

```rust
pub struct Scope<const CELL_SIZE: usize = DEFAULT_CELL_SIZE, M = Local> {
    inner_ptr_: NonNull<ScopeInner<CELL_SIZE>>,
    _mode_: PhantomData<M>,
}

pub type LocalScope<const CELL_SIZE: usize = DEFAULT_CELL_SIZE> = Scope<CELL_SIZE, Local>;
pub type SharedScope<const CELL_SIZE: usize = DEFAULT_CELL_SIZE> = Scope<CELL_SIZE, Shared>;
```

现有 `Scope<CELL_SIZE>` 默认仍等价于 `Scope<CELL_SIZE, Local>`。
`SharedScope` 目前只是类型占位，不能安全构造。

### 4.3 RootScope 泛型

内部：

```rust
pub(crate) struct RootScope<A, const CELL_SIZE: usize, M = Local> {
    scope_inner_: ScopeInner<CELL_SIZE>,
    extension_: RootExtension<CELL_SIZE>,
    allocator_: A,
    _mode_: PhantomData<M>,
}
```

当前只实现 `RootScope<A, CELL_SIZE, Local>` 的初始化；`Shared` root 留给后续。

### 4.4 句柄的当前状态

三种句柄现在也有模式参数：

```rust
Retain<T, M = Local>
Owning<'a, T, M = Local>
Sharing<'a, T, M = Local>
```

当前阶段：

- 只为 `M = Local` 实现构造、解引用、Clone、Drop 等方法；
- `Local` 句柄自动保持 `!Send + !Sync`；
- 不给 `Local` 句柄实现正向 `Send` / `Sync` marker；
- 对应跨线程测试已移除。

未来 `Shared` 模式落地时，再把方法实现扩展到 `M = Shared`，并在满足数据约束后补
`Send` / `Sync` marker。

## 5. 当前限制

1. **默认 root 仍是全局静态**：`DEFAULT_ROOT_SCOPE` 是进程级 `AtomicPtr`。
   多个线程仍可以各自调用 `Scope::new()`，从而共享同一个 root 弱池。
   要严格做到“LocalScope 单线程”，后续应改为：
   - 线程本地 root；或
   - 显式 LocalRoot owner；或
   - 要求用户为每棵树提供 root。
2. **handles 的 `Shared` 模式实现未落地**：类型参数已加上，但当前只有 `M = Local`
   的构造与方法；完整约束见 §4.4。
3. **`TEST_LOCK` 仍保留**：现在主要用于类型级 `PreDrop` 注册表的跨用例隔离，
   而不是 root 弱池同步。

## 6. 下一步

1. 设计 LocalRoot / 线程本地默认 root，消除 `Scope::new()` 的跨线程共享；
2. 为 `Retain` / `Owning` / `Sharing` 增加 `M = Shared` 的方法实现与数据约束；
3. 再设计 `SharedScope`：
   - `T: Send + Sync` 插入约束；
   - 每父域子链锁；
   - root 弱池 / 注册表 / teardown task 锁；
   - `SharedScope: Send` / `SharedScope: Sync` 的安全条件。
