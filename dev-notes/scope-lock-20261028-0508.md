# Scope 锁化实验（feat/scope-lock）

- 分支：`feat/scope-lock`
- 日期：`2026-10-28 05:08`
- 状态：**可编译、库测试通过的原型**；实体回收与 `?Sized` 登记尚未接通

## 目标

把 `Scope` 变成可多线程共享的域句柄：

- 每个域由一把 `CooperativeRwLock<ScopeInner>` 保护，所有放入 / 修改串行化；
- 每域一份用户指定的池分配器 `A`，创建后不再需要泛型 `C`；
- `Scope` 可 `Clone`，所有克隆指向同一个实体；
- `ScopeInner` 不单独做堆分配。

## 落地形状

```text
RootScope {
    scopes_: SpinMutex<BPlusTree<NonNull<ScopeInner>, ()>>, // 按锁内 ScopeInner 地址登记
    metas_:  BPlusTree<usize, *const ()>,                   // 暂未接入同步
    alloc_:  &'static (dyn Allocator + Send + Sync),        // 分配实体
}

ScopeEntity<A> {          // 单块分配，A 为用户指定的每域分配器
    header_: ScopeHeader,
    alloc_:  A,
}

ScopeHeader {
    lock_:    CooperativeRwLock<ScopeInner, …, &'static (dyn Allocator + Send + Sync)>,
    handles_: AtomicUsize,
    closed_:  AtomicBool,
    root_:    &'static RootScope,
    key_:     NonNull<ScopeInner>,
}

Scope { header_: NonNull<ScopeHeader> }   // Clone 只加锁外句柄计数
```

`ScopeHeader` 首字段是锁，因此 `Scope` 的指针也等价于实验设计里的
`NonNull<CooperativeRwLock<ScopeInner>>`。`ScopeInner` 内联在锁的 `UnsafeCell` 里；
每域 `A` 内联在实体尾部，`ScopeInner::allocator_` 用 `NonNull<dyn Allocator + Send + Sync>`
指向它，因此 `ScopeInner` 自身没有第二次堆分配。

## 关键决策

- **固定锁类型**：`ScopeLock = CooperativeRwLock<ScopeInner, …, &'static (dyn Allocator +
  Send + Sync)>`。core 对 `&A` 有 `AllocatorClone` 的 blanket impl，所以锁的 `A` 可以
  擦成引用；非泛型 `Scope` 因此能直接命名锁并 `.write_async().await`。锁内核（`Arc<RwCore>`）
  使用 root 的 `'static` 分配器，不用每域的 `A`。
- **每域分配器内联**：`A` 作为 `ScopeEntity<A>` 的尾部字段；实体由 root 分配器分配一次，
  地址稳定后 `ScopeInner::allocator_` 指向 `A`。`page_size_` 来自 `C::PageSize`，随实体保存。
- **Root 只存登记**：实体是变量大小（含 `A`），不能作为 B+ 树的固定 `V`；树存
  `NonNull<ScopeInner>` 键，实体由 root 分配器单块分配。树的修改由 root 的
  `SpinningMutexOwned` 串行化。
- **Clone + 引用计数**：`handles_` 在锁外，`Clone`/`Drop` 只做原子操作；最后一个句柄只
  置 `closed_`，实体暂不回收（见 TODO）。
- **异步入口**：`Scope::put_async` → 自由函数 `scope_put_async_`（`gen_may_cancel_future`）
  → `lock.acquire_session().write_async().may_cancel_with(cancel).await` → 同步的
  `ScopeInner::put_value_`。锁 future 自身支持取消，drop 会撤销等待节点。
- **安全边界**：`ScopeInner` / `RootScope` / `Scope` 手工 `unsafe impl Send/Sync`。理由是
  池链只在写锁下访问、弱槽位对 `Retain` 的并发访问走原子状态、分配器要求 `Send + Sync`。

## 与最初建议的偏差

- **没有使用 StrongChunk**。每域 `A` 使实体尺寸随类型变化，而 StrongChunk 的 `T` 必须
  具体；另外 StrongChunk 是用户对象容器（强计数、弱身份、predrop），把域实体放进去会把
  Scope 生命周期绑到用户对象机制上。当前方案是一次实体分配 + 树里登记地址，ScopeInner
  仍然内联在锁里，没有额外分配。
- 实体回收、`metas_` 的 root 级同步、`TrScope` 的异步 emplace 尚未接入。

## 测试

新增 2 个 `scope_::tests_` 测试（中英双语文档注释）：

1. `scope_clone_shares_locked_entity_and_uses_per_scope_allocator`
   - 用计数分配器创建域并克隆；
   - 两次 `put_async` 都成功读回，计数分配器被调用 → 证明每域 `A` 生效、克隆共享实体。
2. `scope_lock_serializes_puts_across_threads`
   - 4 个线程各自建 compio Runtime，通过克隆的 `Scope` 并发放入；
   - 全部读回自己的值 → 证明锁与句柄计数跨线程可用，且 `Scope: Send + Sync`。

## 已知问题 / TODO

1. 实体和 `A` 当前永不回收：最后一个 `Scope` 句柄只置 `closed_`；`Retain` 可能仍指向
   实体拥有的槽位，回收需要与最后一个 `Retain`、root 待回收队列和清盘协调。
2. `RootScope::metas_` 还没有自己的锁；`get_meta_` 等方法仍是 `&mut self`，接入
   `?Sized` 登记时必须纳入 root 锁或与 `scopes_` 合并。
3. `ScopeInner::emplace_value_with_` 需要 `meta_addr`，还要把 root 的 meta 登记接进
   `scope_emplace_with_predrop_async`；目前 `TrScope` 的异步 emplace 仍返回 `ClosedScope`。
4. 锁错误（`Cancelled` / `Poisoned`）目前被映射成 `ScopeError::ClosedScope`；需要决定是否
   新增公开错误变体。
5. `Scope::new_from_parent` 暂未表达父子关系；`try_put*`、`collect`、`set_pre_drop` 仍是
   旧的同步 `todo!()`。
6. 类型擦除析构仍是 `todo!()`，测试里用 `mem::forget` 暂避 `Retain::drop`。
