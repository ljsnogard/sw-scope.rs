# RootScope：共享扩展 + 分配器定位 root

- 日期：2026-09-22 16:28
- 模块：`scope_inner_`（`mod` / `life_` / `alloc_` / `teardown_` / `root_` / `tests_`）
- 状态：**已落地**
- 相关：`weak-20260922-1135.md`（D2d 的旧结论已被本文取代）、
  `scope-20260922-1423.md` §8（下一步计划）、`atomic-20260922-1541.md`（锁）

## 1. 旧结论的代价

D2d 把树级共享资源（弱槽位池链、类型级 `PreDrop` 注册表）做成"由 root 分配、再把指针复制进
每个 `ScopeInner`"，理由是 `RootScope` 对分配器类型 `A` 泛型、在 `Scope` 一侧已被擦除，拿不到
它的字段。代价：归属名不副实，且每个域白背 16 字节。

## 2. 设计：三段式布局，分配器永远放最后

```rust
#[repr(C)]
struct RootExtension<const CELL_SIZE: usize> {   // root 比普通域多出来的东西
    weak_pools_: Option<NonNull<WeakPool<CELL_SIZE, RootExtension<CELL_SIZE>>>>,
    pre_drop_registry_: PreDropRegistry,
}

#[repr(C)]
struct RootScope<A, const CELL_SIZE: usize> {
    scope_inner_: ScopeInner<CELL_SIZE>,        // root 自己的域状态（与普通域同型）
    extension_: RootExtension<CELL_SIZE>,       // 共享内容
    allocator_: A,                              // 具体分配器，永远最后
}
```

- 共享资源真正挂在 root 上，`ScopeInner` 不再各存一份（每域省 16 字节）；
- 分配器内联在 root 里，**不泄漏**；
- `RootExtension` 是与 `A` 无关的具体类型，擦除侧可以直接读。

## 3. 任意域（含空域）O(1) 定位 root

每个 `ScopeInner.allocator_: &'static dyn Allocator` 指向 root 的 `allocator_` 字段。既然分配器
永远在最后，回退一个**编译期常量**就得到 root 的任意内容：

```text
extension = allocator_ptr - size_of::<RootExtension>()
root 域   = allocator_ptr - size_of::<ScopeInner>() - size_of::<RootExtension>()
```

这不需要知道 `A`，也不需要 `ScopeInner` 多存任何定位字段（空域照样成立——第一次 `put` 需要
root 的弱池与注册表时，还没有任何强块）。唯一前提是**分配器字段之前没有对齐填充**，初始化时
用 `offset_of!(RootScope<A, _>, allocator_) == size_of::<ScopeInner>() + size_of::<RootExtension>()`
断言（默认的 `Global` 与常见 ZST 分配器都满足）。

> 中途曾用"擦除门面（`RootAlloc`）+ 共享前缀（`RootShared`）"实现同样的定位：功能等价，但多
> 了一个转发类型与一次动态转发。评审后按"三段式 + 分配器最后"收敛，删掉了那层门面。

## 4. 另一条路：强块 → 弱槽位 → 弱池 → root

`RootExtension::of_weak_(weak)` 实现这条关联函数（强块那一跳用现成的
`StrongChunkBase::weak_chunk()`）。"弱槽位 → 弱池"是 O(1) 反向换算，但**不能只减池头**：

```text
pool = slot_addr - (HEADER_BYTES + pool_order_ * SLOT_SIZE)
```

`pool_order_` 是槽位序号，池构造时按数组下标写死、终生只读（归还槽位只重置状态与空闲链，
**不会**重置它），因此空闲槽位同样可用。

**踩过的坑**：第一版只减了 `HEADER_BYTES`，于是除 0 号槽位外，反推结果都落在池的中段，读出
的 `root_` 是垃圾（表现为 `None`），第二个 `put` 就 panic。教训：槽位序号是换算的一部分，
`pool_order_` 不是装饰性的诊断字段。

## 5. 文件拆分（按内聚）

`scope_inner_` 的旧单文件曾膨胀到 800 余行，现按"紧密共享同一组字段的操作放在一起"拆成目录：

| 文件 | 内容 |
| --- | --- |
| `mod.rs` | 常量、`PoolIndex`、`ScopeInner` 字段定义与逐项导出（字段定义在此，子模块才能互访私有字段） |
| `life_.rs` | 域标志与父子 / 兄弟链 |
| `alloc_.rs` | 强池 / 弱池分配与对象构造管线 |
| `teardown_.rs` | 清盘方案 A：关闭、静默判定、待回收名单、回收 |
| `root_.rs` | `RootExtension` / `RootScope` / 一次性初始化 / root 定位 |
| `tests_.rs` | root 与反推路径的单元测试 |

字段一律不公开（不设 `pub(crate)` 字段），跨模块只经关联函数访问，例如
`WeakChunk::chunk_state()`、`WeakChunk::record()`、`RootExtension::weak_pools_head_()`。

## 7. 遗留

- **对齐前提**：若某个自定义分配器的对齐会在 `RootExtension` 之后引入填充，初始化断言会失败。
  届时的改法是让 `RootExtension` 带上与 `A` 对齐匹配的显式填充，或退回"门面"方案。
- `RootScope` 一次性初始化的抢占仍是裸 `compare_exchange_weak`（见 `scope-20260922-1423.md`
  §8.2 的表格）；若要收口，可加一个 `try_claim_once` 原语。
- `ScopeInner::flags_` 的锁接入与"锁守护什么范围"仍待定（同 §8.4）。
