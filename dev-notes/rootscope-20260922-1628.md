# RootScope：树级共享资源的真正归属与 O(1) 反推路径

- 日期：2026-09-22 16:28
- 模块：`scope_inner_` / `weak_/pool_` / `scope_`
- 状态：**已落地**
- 相关：`weak-20260922-1135.md`（D2d 的旧结论已被本文取代）、
  `scope-20260922-1423.md` §8（下一步计划）、`atomic-20260922-1541.md`（锁）

## 1. 旧结论的代价

D2d 当时把树级共享资源（弱槽位池链、类型级 `PreDrop` 注册表）做成"由 root 分配、再把指针
复制进每个 `ScopeInner`"，理由是 `RootScope` 对分配器类型 `A` 泛型、在 `Scope` 一侧已被擦除，
拿不到它的字段。代价：

1. **归属名不副实**：root 只是分配者，每个域都各存一份 `weak_pool_` / `pre_drop_registry_`；
2. **每个域多背 16 字节**：这两份副本在 `ScopeInner` 里纯属重复。

## 2. 设计：共享前缀 + 内联分配器 + 擦除门面（不泄漏）

三块结构，`A` 始终内联在 root 里，不泄漏：

```rust
#[repr(C)]
struct RootAlloc { allocator_: &'static dyn Allocator }   // 具体类型的擦除门面，转发分配/释放

#[repr(C)]
pub(crate) struct RootShared<const CELL_SIZE: usize> {
    scope_inner_: ScopeInner<CELL_SIZE>,   // 第一个字段：root 域指针与本结构指针同址
    alloc_: RootAlloc,                     // 各域的 allocator_ 指向它
    weak_pools_: Option<NonNull<WeakPool<CELL_SIZE, RootShared<CELL_SIZE>>>>,
    pre_drop_registry_: PreDropRegistry,
}

#[repr(C)]
pub(crate) struct RootScope<A, const CELL_SIZE: usize> {
    shared_: RootShared<CELL_SIZE>,
    allocator_owner_: A,                   // 具体分配器内联，终身由 root 持有
}
```

- **共享资源真正挂在 root 上**：弱池链与注册表是 `RootShared` 的字段，`ScopeInner` 不再各存
  一份，每域省 16 字节。
- **不泄漏分配器**：`A` 内联在 `RootScope` 中，`RootAlloc` 只持有指向它的
  `&'static dyn Allocator`。

## 3. 空域也能 O(1) 找到 root：分配器指针反推

`ScopeInner.allocator_: &'static dyn Allocator` 指向 root 里的 `alloc_` 门面字段，它同时承担
"分配"与"定位 root"：

```text
root = allocator_ptr - offset_of!(RootShared, alloc_)
```

关键点：**这个偏移是编译期常量，与 `A` 无关**。若直接让各域持有指向具体 `A` 的
`&dyn Allocator`，回退量就会依赖 `A` 的大小/对齐（这正是 D2d 当年绕不开的擦除问题）；插入一层
具体类型的门面后，回退量退化成 `offset_of!`，既不需要知道 `A`，也不需要任何对齐前提。于是
**空域**（还没有任何强块，但第一次 `put` 就需要 root 的弱池与注册表）也能立刻找到 root。

## 4. 另一条路：强块 → 弱槽位 → 弱池 → root

`RootShared::of_weak_(weak)` 实现这条关联函数（强块那一跳用现成的
`StrongChunkBase::weak_chunk()`）。"弱槽位 → 弱池"是 O(1) 反向换算，但**不能只减池头**：

```text
pool = slot_addr - (HEADER_BYTES + pool_order_ * SLOT_SIZE)
```

`pool_order_` 是槽位序号，池构造时按数组下标写死、终生只读（归还槽位只重置状态与空闲链，
**不会**重置它），因此空闲槽位同样可用。

**踩过的坑**：第一版只减了 `HEADER_BYTES`，于是除 0 号槽位外，反推结果都落在池的中段，读出
的 `root_` 是垃圾（表现为 `None`），第二个 `put` 就 panic。教训：槽位序号是换算的一部分，
`pool_order_` 不是装饰性的诊断字段。

## 5. 落地与验证

- `WeakPool` 新增 `HEADER_BYTES`（`HEADER_SLOT_COUNT * SLOT_SIZE`）与 `of_slot_`（对齐校验 →
  读 `pool_order_` → 反推池）；`weak_pool_of_` 因此从"沿池链线性查找"变成 O(1)。
- `RootShared::of_weak_` 实现槽位反推；`ScopeInner::root_` 用分配器门面反推 root，并以槽位
  反推做 `debug_assert` 自检。
- `Scope::new` 改从 `RootShared::inner_()` 取 root 域。
- `cargo test -p sw-scope`：lib **43** + 集成 6 + 5 + 3，默认与
  `--features strict-put-after-close` 全绿；`root_scope_owns_shared_pools_and_is_reachable_from_slots`
  覆盖"空域经分配器反推 + 400 个对象跨两个弱池后经槽位反推"。
- `cargo clippy` 0 error，新增代码零告警。

## 6. 遗留

- 分配多经一层门面（`RootAlloc` → 具体 `A`）：建池/销毁池路径上多一次动态转发，未出现在
  每对象热路径。
- `RootScope` 一次性初始化的抢占仍是裸 `compare_exchange_weak`（见 `scope-20260922-1423.md`
  §8.2 的表格）；若要收口，可加一个 `try_claim_once` 原语。
- `ScopeInner::flags_` 的锁接入与"锁守护什么范围"仍待定（同 §8.4）。
